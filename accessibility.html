Track 01

Accessibility documentation

Design and build for real-world users from day one. Core documentation blocks your nonprofit team should maintain.

Design rules

Define defaults so new pages start accessible:

  • Color contrast minimums for text and controls
  • Type scale with comfortable line height and spacing
  • Clear link and button states including visible focus

Content standards

Create editorial guardrails for contributors:

  • Heading hierarchy rules for screen reader navigation
  • Alt text guidance for informative and decorative images
  • Plain-language checks for readability and clarity

QA checklist

Run this before every launch:

  • Keyboard-only pass across menus, forms, and dialogs
  • Screen reader spot-check on critical user journeys
  • Automated scan for common WCAG issues
